## What

Adds an experimental `POST /llm/parse` endpoint that uses a local LLM (via Ollama) to turn a free-text query into the query-builder JSON tree, leaving every OMOP concept blank for the existing resolver to fill in. Opt-in and isolated: with `OLLAMA_URL` unset the endpoint returns 503 and nothing else changes. `/extract`, `/concepts/search` and `QueryParser` are untouched.

## Why

Today the query-builder tree is assembled by regex in the NLP service plus ~600 lines of tree-rebuilding in the Laravel `RuleBuilderService`, which even rewrites `"adults with cancer or diabetes"` into `"adults with (cancer or diabetes)"` before parsing. Deciding *structure* — what is OR'd, what nests, what is a demographic rather than a clinical term — is what an LLM is good at and where the regex pipeline is most brittle. Deciding *which OMOP concept* is the opposite: it needs the vocabulary DB, scoring tiers and synonyms, and an LLM would hallucinate concept ids. This POC splits the two along that line so the idea can be judged on real queries before anything larger is committed to.

## Testing

`pytest` — 191 pass, 52 new, none of the existing tests changed. New tests need neither Ollama nor a database: the model client and `resolver.search` are both mocked, and `plan_to_tree` is a pure function.

Verified end to end against `qwen3:8b` and the live vocabulary DB. `adults with cancer or diabetes` produces `demographics.age [18,120]`, a root group of two leaves joined by `or`, and both concepts resolved with alternatives. Also confirmed correct on nested groups (`insulin (glargine or detemir)`), negation (`without eczema`), death (`people who died` / `still alive`), age bands (`teenagers` → 13-19), relative time windows (`in the last 2 years` → `timeConstraint` on the leaf), per-rule age (`under 60 when they suffered a hip fracture` → `ageConstraint`), numeric thresholds (`BMI over 30` → `valueAsNumber`) and race (`black men over 60`).

`notebooks/llm_endpoints.ipynb` carries the full query set used to exercise this, including the cases the platform does not support.

Concept quality matches the existing pipeline exactly — `/extract` returns the same top match for `cancer`, including the same imperfect one (`Serum CA 125 measurement`). This PR neither improves nor regresses concept resolution.

## Notes

- Deliberately not wired to Laravel or the web app. The tree matches what `/v1/parse-query` already returns, but nothing consumes it yet — this is inspected with `curl`.
- The model emits a compact intermediate "plan" which `plan_to_tree` converts into the tree. UUID minting and infix operator interleaving are mechanical and belong in code, and Ollama's schema-to-grammar compilation is unreliable for recursive schemas. The raw plan is returned in the response so a bad result can be attributed to the model or to the conversion.
- Thinking is disabled (`"think": false`, with a fallback for models that lack the mode). Measured at 112.7 s with thinking against 6.1 s without, for byte-identical output.
- `RESOLVER_MAX_MATCHES` is only honoured by the fuzzy resolver; the SQL resolver ignores it and defaults to 25, so `/extract`'s "defaults to RESOLVER_MAX_MATCHES" parameter description is inaccurate for the default backend. Pre-existing and untouched here; `/llm/parse` sets an explicit default of 10 to match what the Laravel API already requests.
- The plan covers every field the web `Demographics` type and `Node` type expose except `location`: age, sex, race, death, `exclude`, `timeConstraint`, `ageConstraint`, `valueAsNumber` and their operators, plus `and`/`or`/`followed_by`.
- Where a query is ambiguous between the patient's current age and their age at the event, the endpoint states which reading it took, matching the wording `RuleBuilderService` already uses for `"Adults" interpreted as current age >= 18`.
- Unsupported-feature warnings reuse `RuleEngine.find_unsupported_features()`, so `/llm/parse` and `/extract` now agree on what they warn about. Previously only `/extract` warned.
- Adds `GET /llm/models` listing pulled models and which are resident in memory.
- Not modelled: `location` (geographic filtering), occurrence counts, consecutive-day windows.
